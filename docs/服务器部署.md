# 独立部署：Debian + Nginx + HTTPS

建议用新子域名，例如 `gateway.你的域名`。不要覆盖原洗衣机的站点配置。本教程中的 `gateway.example.com`、服务器IP、邮箱都要替换。
服务器账号密码不包含在项目中，也不需要写入ESP。公网只开放80/443和你的SSH端口；Python服务8766只绑定127.0.0.1。

## 1. DNS与本地配置
给子域名创建A记录指向服务器公网IP。如果有AAAA记录，也要确保对应IPv6可达，否则删除无效AAAA。
按主README运行server/configure.py，origin填写 `https://gateway.example.com`，设备ID与ESP一致。只把 `server.json` 上传服务器；device-token.txt由你本地保管。

上传整个server目录（注意不要把private里的令牌文件一同上传）最简单的方法是单独复制这些文件：
```
server.py
index.html
requirements.txt
gateway.service
nginx.conf.example
```
将它们放入服务器 `/opt/esp-gateway/server/`。将生成的server.json放入 `/etc/esp-gateway/server.json`。

## 2. 系统服务
以root执行（事先确认这些专用路径未被其他项目使用）：
```bash
apt update
apt install -y python3-venv python3-pip nginx certbot
useradd --system --home /opt/esp-gateway --shell /usr/sbin/nologin esp-gateway
mkdir -p /opt/esp-gateway/server /etc/esp-gateway
python3 -m venv /opt/esp-gateway/venv
/opt/esp-gateway/venv/bin/pip install -r /opt/esp-gateway/server/requirements.txt
chown root:esp-gateway /etc/esp-gateway /etc/esp-gateway/server.json
chmod 750 /etc/esp-gateway
chmod 640 /etc/esp-gateway/server.json
chmod -R a+rX /opt/esp-gateway/server
cp /opt/esp-gateway/server/gateway.service /etc/systemd/system/esp-gateway.service
systemctl daemon-reload
systemctl enable --now esp-gateway
systemctl status esp-gateway --no-pager
curl -I http://127.0.0.1:8766/
```
若账号已存在，不重复useradd。服务用户无需写入源码或配置。配置与源码由root维护。

## 3. 先开HTTP验证域名
创建 `/etc/nginx/sites-available/esp-gateway`：
```nginx
server {
    listen 80;
    server_name gateway.example.com;
    location /.well-known/acme-challenge/ { root /var/www/gateway-acme; }
    location / { return 200 "Gateway certificate setup"; }
}
```
执行：
```bash
mkdir -p /var/www/gateway-acme
ln -s /etc/nginx/sites-available/esp-gateway /etc/nginx/sites-enabled/esp-gateway
nginx -t
systemctl reload nginx
certbot certonly --webroot -w /var/www/gateway-acme -d gateway.example.com --email 你的邮箱 --agree-tos --key-type rsa
```
若失败，先检查DNS、防火墙和80端口。不要跳过错误继续配置不存在的证书。

## 4. 切换HTTPS
把提供的nginx.conf.example中的域名全部改为真实域名，替换上一步专用站点文件。不要修改其他站点。
```bash
nginx -t
systemctl reload nginx
systemctl enable --now certbot.timer
certbot renew --dry-run
```
添加续期后reload脚本 `/etc/letsencrypt/renewal-hooks/deploy/esp-gateway-nginx.sh`：
```sh
#!/bin/sh
nginx -t && systemctl reload nginx
```
赋予可执行权限 `chmod 755 /etc/letsencrypt/renewal-hooks/deploy/esp-gateway-nginx.sh`。

用浏览器打开真实HTTPS域名登录。必须与server.json的origin完全一致，包括协议和非默认端口，不含结尾斜线。服务器会检查浏览器Origin和会话CSRF令牌。

ESP配置：主机真实域名、443、`/gateway/ws`、开启TLS、设备ID和独立令牌。内置CA为ISRG Root X1；证书链不匹配时，在面板粘贴正确CA，不要关闭公网TLS。

## 5. 新增设备与账号维护
在安全环境运行：
```bash
python server/add_device.py --config server/private/server.json --device seedling-02 --token-out seedling-02-token.txt
```
上传更新后的server.json，保持root:esp-gateway和640权限，然后 `systemctl restart esp-gateway`。给新设备配置自己的ID与新令牌。每台网关占用独立槽位；同一ID同时连接会被拒绝。

当前参考服务为单管理员模式。登录后可在“账号设置”中修改用户名和密码，新密码最低8位，必须验证当前密码。修改会清除所有旧会话，不改变设备令牌。

网页修改后的凭据保存在 `/var/lib/esp-gateway/account.json`，优先于server.json。忘记密码时，可由服务器root先备份并移走此覆盖文件，再更新server.json内username/password_salt/password_hash并重启。不要只改初始server.json却保留旧的覆盖文件。备份应同时包含两个文件。

## 6. 诊断与更新
```
journalctl -u esp-gateway -n 100 --no-pager
nginx -t
systemctl status esp-gateway --no-pager
```
- HTTP401：检查设备ID和令牌是否配对；网页登录与设备令牌是两套凭据。
- HTTP409：相同ID已有连接，或设备未在线/处于只读。
- 页面请求来源不匹配：检查origin是否是实际访问的网址，不要混用IP和域名。
- WSS连接失败：检查NTP校时、证书链、主机名、443端口及nginx Upgrade头。
- 网关在线但无RX：检查MCU是否主动发送、共地、RX/TX交叉、电平、波特率、文本换行。
- 发送成功但无动作：网关ACK不是执行ACK；检查MCU命令解析，查看RX反馈。

备份源码、server.json与相应令牌。日志与登录会话在内存中，服务器重启清空；本参考服务没有持久历史数据库。不要将private目录作为Nginx静态目录公开。

更新服务器代码后重启服务；更新ESP程序需要USB烧录，本版没有OTA。更新业务功能但保持Gateway v1与串口设置兼容时，无需改ESP固件。
