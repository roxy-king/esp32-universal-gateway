# Gateway v1 上的项目协议 P1

ESP 固件保持不变。它负责 TLS、鉴权、WebSocket、命令有效期、串口转发；P1 是串口负载中的项目协议。固定9600/8N1、CRLF，ASCII，帧最大95字符输入/512字节上报。

## 控制

`P1,C,bench,12ab34cd,PULSE,5`

依次为版本、控制类型、项目ID、8位小写十六进制操作ID、操作名、0–65535整数参数。控制内容由服务端按白名单生成，不接受任意字符串模板。

## 执行回执

`P1,A,bench,12ab34cd,OK,applied`

或 `P1,A,bench,12ab34cd,ERR,out_of_range`。

OK 表示已应用该命令；限时动作的“启动成功”不表示整个周期已完成。完成情况通过状态数据表达。没有物理反馈的 LED 示例只能证明控制状态已设置，不能证明灯珠没有损坏。

## 主动状态

`P1,S,bench,led=1;remaining=5;uptime=12`

单片机每秒上报一次，操作后也上报。字段名和范围必须与 project.json 相同。缺失、重复、越界、项目ID不同的帧不会更新有效状态。

## 结果处理

- Gateway v1 ACK 只确认入队。项目平台等待匹配设备/项目/操作ID的 P1 回执，最多10秒。
- 超时为 unknown，不自动重发；迟到的合法回执可以更新记录。
- 单片机缓存最近8个操作ID。相同ID、相同内容只回原结果，不重新执行；相同ID不同内容拒绝。
- 单片机重启会清空去重缓存，不能提供掉电永久幂等。高风险动作应增加非易失序号或业务幂等设计。
- 项目状态10秒未更新会禁止新的即时操作。预约到时同样检查；服务端离线不等于本地设备停止。
- P1 不带应用CRC。串口参数、接线和电平正确是前提；需要强抗干扰或更强完整性的项目应扩展CRC并同时更新解析/测试。

## 项目扩展

数值协议是为8051资源限制设计的最小通用基础。温度可上报放大10倍后的整数并在页面换算；负温度可约定偏移。多参数动作、字符串、权限分级或硬实时控制不应硬塞入一个整数，必须显式扩展契约。
