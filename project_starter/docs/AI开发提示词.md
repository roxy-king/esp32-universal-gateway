# 复制给 AI 的开发请求

请读取本工程 AGENTS.md、README.md、project.json、docs/项目需求表.md 和 docs/通信协议.md，基于填写的需求完成新项目。

保留 Gateway v1 与现有 ESP 固件。复用平台的登录、设备鉴权、状态记录、执行链路、预约和 AI 确认机制。不能将旧洗衣机的模式、阶段或时间字段硬编码到新项目。

请完成：

1. 核对硬件型号、实际引脚、时钟与电平，列出真正缺失的信息，不伪造驱动或读数。
2. 更新 project.json，统一字段单位、缩放方式、命令名称、范围、确认要求和 AI/预约权限。
3. 实现 firmware/logic.c 的真实业务驱动和状态机；同步 main.c 的硬件初始化与上报字段。保留 UART1 P3.6/P3.7，避开 Timer2 冲突；本地实现安全时限和故障处理。
4. 按项目设计 platform/index.html 专用布局。可复用自动生成的基础表单，但无需强套示例外观，不制作拖拽面板。
5. 若协议超出单整数参数/整数字段范围，同步扩展固件、服务端、AI输入校验和测试。不要绕过统一 execute 路径。
6. 运行配置检查、Keil编译、自动化测试和桌面/手机浏览器验证，提供 HEX、源码和部署方法。
7. 有明确目标服务器授权后才部署；先备份。不要覆盖旧项目，不把密钥或私有配置提交到仓库。
8. 给出按顺序可操作的实机验收表。分别报告模拟验证、编译验证和实机验证结果。

需要服务器访问时，请使用用户提供的访问方式；域名本身不是登录凭据。不要要求用户将密码写进公开的需求表。
