# 部署与回退

## 先理解两种服务

原来的 `/opt/esp-gateway` 是通用收发控制台。本模板的项目服务直接支持相同 Gateway v1 WebSocket，同时增加业务界面与协议解析。它作为独立服务安装，不需要两个服务互相转发，也不覆盖旧服务。

同一 ESP 一次只连接一个服务器地址。切换新项目时，需要将 ESP 的服务器域名和设备令牌改为新项目的值；ESP 固件不变。不要把同一令牌配置到两台同时运行的设备。

## 部署已完成适配的项目

1. 在本机完成 `python tools/project.py check --generate`、编译、自动化和模拟测试。
2. 将新项目独立域名解析到服务器，开放80/443。不同项目可用 `nursery.example.com`、`monitor.example.com` 等子域名。
3. 上传**不含 private/、.venv/、编译缓存**的完整项目目录到服务器。
4. SSH登录，以root运行：

```bash
python3 deploy/install.py --domain nursery.example.com --email 你的真实邮箱 --port 8767
```

安装器支持 Debian/Ubuntu，使用 apt 安装依赖、独立 Python venv、systemd、nginx 和 Certbot HTTPS。先查看计划可加 `--dry-run`。新安装交互设置网页登录密码；升级保留原账号和数据。

服务/目录以 project.json 的 id 区分。例如 id 为 nursery：

| 内容 | 路径 |
| --- | --- |
| 服务 | link-project-nursery |
| 版本目录 | /opt/link-project-nursery/releases/ |
| 当前版本 | /opt/link-project-nursery/current |
| 登录哈希和设备令牌哈希 | /etc/link-project-nursery/server.json |
| ESP配对信息，含私密令牌 | /etc/link-project-nursery/pairing.json |
| 数据库、账号修改、网站设置、AI密钥 | /var/lib/link-project-nursery/ |

配置 ESP 时，从 pairing.json 读取 host、port、path、tls、token；不要把该文件上传公开仓库。仅在自己控制的终端查看令牌。设置9600/8N1/line/CRLF，先观察上报，再开启远程写入。

## 直接安装未经改造的 LED 示例

发布后也可从 GitHub 获取模板安装器。这只安装 **LED 示例**，不会自动变成育苗业务：

```bash
f=$(mktemp) && curl -fsSL https://raw.githubusercontent.com/roxy-king/esp32-universal-gateway/v1.7.0/project_starter/install.sh -o "$f" && bash "$f" demo.example.com 你的真实邮箱 8767; r=$?; test -z "$f" || rm -f -- "$f"; exit "$r"
```

将域名和邮箱替换成自己的。更改业务后应上传自己的工程运行 deploy/install.py，不能再用上面命令覆盖为默认 LED 示例。

## 更新与回退

将同一项目ID的新版本上传，使用相同域名和端口再次运行安装器。安装器创建新版本目录，保留私有配置和数据库，切换 current，检查本机 /health；更新失败时回退旧代码。

查看/执行上次代码回退：

```bash
python3 deploy/rollback.py nursery
python3 deploy/rollback.py nursery --apply
```

回退不恢复数据库、固件或外设状态。跨数据库结构版本迁移需要另做备份/恢复方案，不能假定旧代码兼容新数据库。

备份数据时先停止相应项目服务，再复制 `/var/lib/link-project-项目ID` 和 `/etc/link-project-项目ID`；备份同样含密钥，不公开上传。本站点的示例账号/密码仅存在于本机模拟模式，生产部署无通用默认密码。

## 检查与排错

```bash
systemctl status link-project-nursery --no-pager
journalctl -u link-project-nursery -n 60 --no-pager
curl -fsS http://127.0.0.1:8767/health
```

- ESP离线：检查ESP自身Wi-Fi、域名、TLS、时钟和独立令牌。
- ESP在线但无项目状态：检查烧录的是否为该项目固件、项目ID、RX/TX、共地、电平、波特率和P1字段。
- 入队但结果未知：查看单片机是否返回匹配ID的P1回执，不要反复重发有副作用的操作。
- AI不可用：检查设置中的HTTPS Base URL、兼容接口路径、模型名称、Key和额度。不会将设备令牌发给模型。
- 本地模拟成功不证明服务器HTTPS、实际硬件、第三方AI服务已经通过验收，需要分别验证。
