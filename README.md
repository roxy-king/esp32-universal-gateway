# Link / ESP32 通用通信网关 1.6
现成固件仅针对 **ESP32-S3 N16R8（16MB Flash）**。

## 一键部署与自动配对

以 **root** 登录Debian/Ubuntu服务器，复制整行：

```bash
bash -c 'f=$(mktemp) && curl -fsSL https://raw.githubusercontent.com/roxy-king/esp32-universal-gateway/v1.6.1/install.sh -o "$f" && bash "$f"; r=$?; test -z "$f" || rm -f -- "$f"; exit "$r"'
```

若提示curl不存在，先运行 `apt-get update && apt-get install -y curl ca-certificates`。
向导会下载固定v1.6.1源码，安装服务、配置HTTPS并生成ESP配对文件。请先完成独立域名DNS解析，并开放80/443端口。
完成后把 `/etc/esp-gateway/pairing.json` 下载到电脑的 `private/pairing.json`，连接ESP热点并运行 `connect.cmd`；服务器不能替你连接本地设备热点。

也可以从仓库的 **Releases** 下载完整包，使用Windows向导：
双击 **setup.cmd**：SSH上传服务端 → 安装服务与HTTPS → 下载配对凭据 → 连接ESP热点 → 自动写入服务器与Wi-Fi配置。
已部署服务器、只需重新配对时运行 **connect.cmd**。首次域名解析、SSH登录和连接热点仍需按提示操作。
详细步骤：[一键部署与配对](docs/一键部署与配对.md)。

## 已提供

- 脱离电脑的 UART ↔ Wi-Fi ↔ WebSocket/WSS 通信。
- 设备热点内的中文设置面板：项目名、设备ID、Wi-Fi、服务器主机/端口/路径、认证令牌、TLS与CA、NTP、波特率、GPIO、校验位、分包方式与控制权限。
- 文本行和任意二进制字节（HEX封装）；默认9600、8N1、RX18/TX17。
- Wi-Fi重连、云端重连、心跳、开机会话ID、过期命令拒绝、重复命令拒绝、默认只读。
- 状态诊断、事件记录、脱敏配置导出/导入、重启、恢复项目配置。
- 独立服务端：账号登录、多设备注册、远程发送、串口记录、浏览器常用命令。
- 预编译固件、烧录工具、源码、测试与部署模板。

## 先看这一点

通用指“传输不再绑定洗衣逻辑”，不是“不写单片机程序就能控制任意设备”。新项目必须定义可执行命令与状态反馈。旧洗衣机网站的协议不同，本固件不能直接连接原网站。本仓库的安装与烧录脚本仅在用户运行后更改相应设备。

## 第一步：烧录ESP32

1. 整个目录解压到短路径，例如 `D:\ESP32Gateway`。
2. 拔开与单片机之间的信号线也可独立配置；用USB数据线连接ESP32，关闭旧串口监视器。
3. 双击 `flash.cmd`，填写实际COM端口，输入 `FLASH` 确认。此操作会覆盖ESP固件，合并镜像也可能清除此前保存的设置；先记录旧配置。
4. 烧录后点按ESP32的RST；如果连接超时，按住BOOT、点按RST、松开BOOT，再重新烧录。
5. 用串口工具打开USB COM，**115200**。点按RST，读取 `AP: Gateway-Setup-... password: ...`。
   也可先 `py -m pip install pyserial`，再 `py serial_monitor.py COM5`。
6. 手机连接输出的热点。密码为每台设备首次生成的随机密码，不是原来的WasherSetup密码。访问 `http://192.168.4.1`。

普通用户用现成BIN即可，不需要安装Arduino工具链。

## 第二步：先准备独立服务器配置

本机试验（Python 3.11及以上）：
```powershell
cd D:\ESP32Gateway
py -m venv .venv
.\.venv\Scripts\python -m pip install -r server\requirements.txt
.\.venv\Scripts\python server\configure.py
```
按提示输入网页完整地址，例如 `http://127.0.0.1:8766`（仅电脑浏览器试验），或者 `https://gateway.你的域名`（公网）。设备ID可自行命名；ESP 使用独立设备令牌自动配对，无需两边 ID 一致。程序生成：

- `server/private/server.json`：账号哈希和设备令牌哈希。
- `server/private/device-token.txt`：填入ESP面板的设备令牌，仅本地保存。

启动：
```powershell
.\.venv\Scripts\python server\server.py --config server\private\server.json
```
默认只监听127.0.0.1。ESP接入局域网测试时，运行参数增加 `--host 0.0.0.0`，网页地址在生成配置时改为 `http://电脑局域网IP:8766`，放行Windows专用网络的8766入站。ESP填写电脑局域网IP、8766、`/gateway/ws`，临时关闭TLS。**这仅用于可信局域网测试，不向公网暴露明文端口。**

局域网模式也需要校时才能验证命令有效期：允许网关访问NTP（通常UDP123），或在面板填写局域网内可用的NTP服务器。

公网长期运行请按 [服务器部署](docs/服务器部署.md) 配置独立域名与HTTPS。

## 第三步：填写ESP面板

1. 项目名自定；设备ID可保留默认值。服务端 v1.6.0 起按独立令牌识别设备，不要求与服务器登记 ID 一致。
2. 填2.4GHz Wi-Fi名称和密码。密码留空代表保留；换成开放Wi-Fi需勾选清除密码。
3. 主机只填域名/IP，不含 `https://`；公网端口443、路径 `/gateway/ws`，打开TLS。
4. 设备令牌填生成的device-token.txt内容。以后留空保留。不要填网页登录密码。
5. 公网证书链若由ISRG Root X1信任，CA留空即可；其他CA粘贴对应PEM根证书。始终验证证书，不提供“忽略证书错误”。
6. 根据单片机设置串口。先保持“允许远程发送串口命令”关闭，验证数据接收后再开启。
7. 保存并重启。正常Wi-Fi连接后热点不自动开启；**开机完成后长按BOOT 3秒**可重新开热点，不清空项目配置。
8. Wi-Fi未连上超过45秒会自动开热点。云端未连接但Wi-Fi正常时，用BOOT手动开热点查看诊断。

热点开启期间管理HTTP只接受经热点接口进入的连接，不向家庭局域网开放管理页面。热点没有自动关闭计时，配置结束可重启关闭（Wi-Fi配置成功时）。

## 第四步：接单片机

| ESP32 | 电平转换器低压侧 | 高压侧 / 单片机 |
|---|---|---|
| GPIO18（RX） | LV1 | HV1 → 单片机TX |
| GPIO17（TX） | LV2 | HV2 → 单片机RX |
| 3V3 | LV | 不接5V |
| GND | GND | 单片机GND |
| — | — | HV → 单片机5V参考电源 |

两块板分别正常供电。3.3V MCU可用兼容3.3V TTL连接；5V单片机不能直接输出到ESP引脚。
原CT107D兼容固件：P37为TX、P36为RX，按住S4再上电进入ESP串口模式。新育苗固件的引脚以它自身实现为准。

## 第五步：验证远程链路

1. 打开服务器网页登录。未接单片机时，网关也可以显示云端在线；这不表示单片机在线。
2. 让单片机每秒发送 `TEMP,25.5\r\n`，网页应出现RX记录。
3. 在热点面板开启远程写入，保存重启。网页发送单片机确实支持的命令。
4. 观察“已进入串口发送队列”后单片机自己的反馈。不要把网关ACK当成业务执行成功。
5. 换手机移动数据再次登录，检查真正的公网远程链路。
6. 断开Wi-Fi、恢复Wi-Fi、重启ESP，检查自动恢复；断线期间旧指令不会缓存补发。

如果暂无单片机，可断开其所有信号线后，把ESP GPIO17与GPIO18短接做3.3V UART回环，文本模式发送 `PING`，应接收相同内容。完成后移除短接。不要在仍连接单片机TX时短接，以免两个输出端相互驱动。

## 更换项目与常用操作

- 换服务器：BOOT开热点 → 改主机/端口/路径/令牌/CA → 保存重启。不必重新编译。
- 换项目：改单片机程序及命令，调整串口参数；服务端可直接作为原始命令控制台，也可进一步做育苗图表。
- 导出配置不包含Wi-Fi密码和令牌；导入只填表单，不立即保存。
- 恢复出厂清除项目配置，保留本机热点密码；忘记热点密码可USB串口115200查看，不必清空设备。
- 服务端支持多设备，每台设备独立ID与令牌；详见部署文档。
- 本版未提供OTA、MQTT、RS485自动方向控制。当前固件是明确限定硬件的UART/WSS网关，不承诺所有ESP型号通用。

## 修改控制台账号密码

安装时密码最低8位。登录控制台后展开页面底部的“账号设置”，填写用户名、当前密码和两次新密码即可保存；保存后需重新登录，所有旧会话失效。设备ID、设备令牌与ESP配置不变，不需要重刷ESP。

已用本向导安装的服务器，重新运行上面的v1.4.0命令即可更新，保留原账号、令牌与配对文件。首次升级不强迫你修改旧密码；可以登录后再改成8位或更长。
账号修改保存于 `/var/lib/esp-gateway/account.json`，通过systemd StateDirectory限定写入目录。该文件优先于初始server.json内的账号设置，备份时也需包含它。手动启动时默认保存在server.json同目录，也可以传 `--account-file` 指定可写路径。

## v1.5.1：修改配置热点密码（固件 1.2.1）

在设备热点页面“维护 → 配置热点密码”输入当前密码、新密码及确认密码。支持 8～63 位可打印 ASCII 字符；两次新密码必须一致。保存成功后约 2 秒重启配置热点，重新连接时使用新密码；路由器 Wi-Fi、服务器凭据不变。8～11 位自定义密码在设备重启后同样保留。

忘记密码可通过 USB 调试串口 115200 查看。恢复出厂配置仍保留热点密码。此操作仅允许设备热点内携带有效 nonce 的请求，密码不通过配置导出或状态 API 返回。

本版不修改 RGB 灯行为；当前固件未把灯色定义为在线或故障状态。不同板卡的电源灯和 RGB 引脚设计可能不同。

## v1.5.2：RGB 默认关闭（固件 1.2.2）

启动时对当前 esp32s3 板卡定义的 RGB_BUILTIN（GPIO48）写入黑色，正常运行不再点亮 RGB；小红色电源指示灯不受此设置影响。保留 v1.5.1 的热点密码修改功能。其他板型若将 RGB 接到 GPIO38，需要按实际板卡定义编译，不应直接驱动未核实的引脚。

## v1.5.3：烧录后自动显示配网信息

运行 `flash.cmd`，烧录校验成功后会自动在 115200 波特率读取 ESP 启动信息，并显示热点名称、该设备的实际密码和 `http://192.168.4.1`。无需额外安装 Python 或串口助手。请先关闭占用串口的软件。

- 脚本会正常复位一次 ESP，不会额外擦除配置；密码只显示在当前窗口，不保存到日志文件。
- 如果自动复位未触发，可在读取窗口等待时点按 RST。超时不会把已经成功的烧录判定为失败。
- 单独双击 `read-hotspot.cmd`，输入 COM 口，也可以读取当前密码；这个脚本不会烧录。读取时会复位设备，通信会短暂中断。
- 已配置设备可能不开热点；读取后按住 BOOT 4 秒即可开启。
- 全量 `flash.cmd` 原本就可能清除配置；只想查看密码请使用 `read-hotspot.cmd`。
- 本版本固件仍为 1.2.2，无需给现有 ESP 再次烧录。

验证：Windows PowerShell 5.1 脚本语法与解析测试通过（包括分段串口数据、8位密码及密码空格）；COM5 实机成功读取当前热点信息。输出密码不要截图公开。

## v1.6.0：连接状态与设备管理

- 控制台分开显示网页到云端、ESP 到云端、单片机到 ESP。串口长时间没有数据不直接判定单片机离线。
- 配置摘要显示固件、Wi-Fi 信号、串口波特率/格式/引脚、行尾、服务器地址及最近上报时间。完整字段需要固件 1.3.0；旧版仍能连接，缺失项明确显示未上报。密码和令牌不进入摘要。
- 页面默认开启离线提醒，可自行关闭，偏好保存在当前浏览器。只在本次页面观察到在线转离线时提醒，恢复后清除；网页无法访问服务器时显示状态未知，不伪报 ESP 离线。关闭网页后不推送。后台标签页检测可能受浏览器节流影响。
- 展开“设备名称与 ID”即可修改名称与控制台 ID，无需重刷或重配 ESP。它是控制台标识；服务器内部注册键和 ESP 上报 ID 保持不变，历史记录及现有会话继续可用。
- 服务端按独立令牌唯一匹配设备。ESP 的请求头 ID 与自身状态上报仍须一致，但不必与服务器注册键一致。令牌错误或同一个令牌被登记给多台设备时拒绝连接，同一令牌仍只允许一个在线会话。
- 设备名称与控制台 ID 保存于账号文件同目录的 `devices.json`（标准部署为 `/var/lib/esp-gateway/devices.json`）；更新服务保留此文件。它不保存令牌。设备设置接口仍要求登录、正确来源和 CSRF。
- 页面每秒读取一次状态；ESP 每5秒上报心跳，服务端超过20秒无上报视为状态过期。二者不是同一个刷新周期。

验证：29项服务端/部署测试通过；真实浏览器验证设置保存、发送与模拟回复、掉线/恢复、关闭提醒、云端不可达与三种屏宽。固件 1.3.0 在 ESP32-S3 N16R8 编译通过。现有设备升级请仅写应用分区 0x10000；全量 flash.cmd 会重写整片镜像，升级前务必备份配置。

## v1.6.1：配对文件导入（ESP 固件 1.3.2）

完整项目发布版本 v1.6.1 与设备诊断中的固件版本 1.3.2 是两套版本号。

1. 通用网关服务器生成 `/etc/esp-gateway/pairing.json`；项目服务使用 `/etc/link-project-项目ID/pairing.json`。在自己的电脑终端执行 `scp root@服务器IP:/etc/esp-gateway/pairing.json .` 下载；自定义 SSH 端口加 `-P 端口`。文件含设备令牌，不要公开。
2. 将文件下载到手机；连接 Gateway-Setup 热点，打开 `http://192.168.4.1`，进入“服务器与串口”。
3. 选择“导入服务器配对文件”，选中 JSON，核对主机、端口、路径及 TLS 后确认。
4. 导入只填写表单，尚未保存。它替换 host、port、path、tls、token；保留 Wi-Fi、设备 ID、串口参数及远程写入开关。旧自定义 CA 会清空；使用自签名或其他证书链时需补填正确 CA。
5. 检查配置并测试服务器连接，然后点击“保存并重启”。双向控制项目还要确认“远程写入”开启；串口参数须与单片机一致。
6. 重启后确认云端在线，再按项目协议确认单片机应答；仅有串口字节不代表控制执行成功。

支持 schema 为 `gateway-pairing-v1` 或数字 `1` 的配对文件，上限 16KB。格式无效不会覆盖表单；浏览器本地解析，确认预览不展示令牌。原来的手动填写方式仍可使用。

热点网页打不开：确认仍连接设备热点，使用 HTTP；长按 BOOT 约4秒开启热点。手机提示无互联网时保持连接；可换浏览器验证，不能据此认定是服务器证书故障。固件 1.3.2 在有热点客户端连接时暂停失败 Wi-Fi 的周期重试，并增加不含凭据的运行日志。

升级：已有相同分区的 ESP32-S3 N16R8 可仅写 `0x10000` 应用固件以保留 NVS 配置；首次安装使用完整发布包 flash.cmd。全量烧录可能清空配置，请保管自己的配对文件和热点密码。

验证范围：1.3.2 编译及 COM5 写入哈希校验通过；两种配对格式与无效文件拒绝测试通过；用户确认更换浏览器后可访问。真实文件导入、保存与重连仍需按步骤验收，不将模拟测试当成实机验证。
